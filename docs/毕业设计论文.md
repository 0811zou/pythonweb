## Abstract

**Title:** Design and Implementation of an Agricultural Product Traceability and Assistance Platform

**Abstract:** To address issues such as information asymmetry, difficulty in traceability, and limited sales channels for farmers in traditional agricultural product circulation, this paper designs and implements an agricultural product traceability and assistance platform based on the Django framework. The platform adopts a B/S architecture, with the backend using Django REST Framework to build RESTful APIs and the frontend using Bootstrap 5 for a responsive interface. Core features include batch-based product traceability (QR code), online ordering, agricultural subsidy applications, agricultural technology training, and user role-based access control. The system implements independent traceability codes for each product batch through the ProductBatch model, enabling consumers to scan QR codes to view complete lifecycle information from production to distribution. Docker containerization technology is employed for deployment, supporting one-click deployment and automated operations. Test results demonstrate complete functionality and stable performance, effectively connecting farmers with consumers and improving the efficiency and trustworthiness of agricultural product circulation.

**Keywords:** Agricultural product traceability; Django; REST API; QR code; Rural revitalization

## 第一章 绪论

### 1.1 项目背景

近年来，随着我国乡村振兴战略的深入推进，农业数字化转型成为重要发展方向。然而，当前农产品流通过程中仍存在以下突出问题：

1. **信息不对称**：消费者难以获取农产品的产地、生产过程和质检信息，导致信任缺失。
2. **溯源困难**：传统农产品流通链条长、环节多，一旦出现质量问题难以追溯源头。
3. **销售渠道单一**：中小农户缺乏有效的线上销售渠道，中间商层层加价，农户收益偏低。
4. **政策驱动**：国家大力推进"数字乡村"建设，鼓励利用信息技术赋能农业。

在此背景下，开发一个集农产品溯源、在线交易、助农服务于一体的综合平台，具有重要的现实意义和应用价值。

### 1.2 国内外研究现状

**国外方面**，欧美日等发达国家在农产品溯源领域起步较早。欧盟自2002年起实施《食品基本法》，建立了覆盖"从农场到餐桌"的强制溯源体系。日本在2003年推行"牛肉溯源"制度后，逐步扩展至大米、蔬菜等农产品。在技术层面，发达国家广泛采用条码、RFID、区块链等技术实现农产品全流程追溯。

**国内方面**，我国农产品溯源体系建设相对较晚，但发展迅速。2015年以来，国家市场监督管理总局推动建设"重要产品追溯体系"，覆盖食用农产品、食品、药品等领域。在学术研究方面，近年来基于物联网、区块链、大数据的农产品溯源系统成为研究热点。但在实际应用中，大部分溯源系统仍存在数据采集成本高、信息孤岛、消费者参与度低等问题。

本平台在借鉴现有研究的基础上，采用轻量级的二维码批次追踪方案，降低了溯源实施成本，并通过电商功能增强用户粘性，实现溯源与交易的有机结合。

### 1.3 研究意义

1. **社会意义**：响应国家乡村振兴战略，助力农业数字化转型，促进农民增收。
2. **经济意义**：减少农产品流通环节，降低交易成本，提高产业链效率。
3. **技术意义**：探索 Django + REST API 在农业领域的应用实践，形成可复用的技术方案。
4. **学术意义**：为农产品溯源领域提供一种低成本、易推广的技术实现路径。

## 第二章 相关技术概述

### 2.1 Django 框架

Django 是一个基于 Python 的高级 Web 框架，遵循 MTV（Model-Template-View）架构模式。其核心特性包括：

- **ORM（对象关系映射）**：通过 Python 类定义数据模型，自动生成数据库表结构，支持 SQLite、PostgreSQL、MySQL 等多种数据库。
- **内置管理后台**：通过 `django.contrib.admin` 自动生成数据管理界面，便于管理员操作。
- **安全性**：内置 CSRF 保护、XSS 过滤、SQL 注入防护等安全机制。
- **可扩展性**：丰富的第三方包生态（如 Django REST Framework、django-cors-headers 等）。

本平台选用 Django 5.2 作为开发框架，充分利用其完善的 ORM、认证系统和模板引擎。

### 2.2 Django REST Framework

Django REST Framework（DRF）是一个用于构建 RESTful API 的强大工具包，提供了：

- **ViewSet + Router**：通过 ModelViewSet 和 DefaultRouter 快速生成符合 REST 规范的 API 端点。
- **序列化器（Serializer）**：自动实现模型数据与 JSON 格式的相互转换、数据验证。
- **权限控制**：支持 IsAuthenticated、IsAuthenticatedOrReadOnly 等细粒度权限策略。
- **文档生成**：配合 drf-spectacular 自动生成 OpenAPI 规范文档和 Swagger 交互界面。

### 2.3 Bootstrap 5 与前端技术

前端采用 Bootstrap 5 框架，结合 Bootstrap Icons 图标库，实现响应式界面设计。主要特点：

- 移动端优先的栅格系统，适配不同屏幕尺寸
- 丰富的 UI 组件（导航栏、卡片、表单、模态框等）
- 轻量级，无需引入 jQuery 等依赖

### 2.4 容器化与部署技术

- **Docker**：将应用及其依赖打包为轻量级容器，保障环境一致性。
- **Docker Compose**：通过 YAML 配置文件定义多容器应用，支持一键部署。
- **Gunicorn**：高性能 Python WSGI HTTP 服务器，用于生产环境部署。
- **WhiteNoise**：在 WSGI 层面直接提供静态文件服务，无需额外配置 Nginx。

### 2.5 Swagger / OpenAPI

OpenAPI 规范（原 Swagger Specification）是 RESTful API 的行业标准描述格式。drf-spectacular 自动从 Django 代码（ViewSet、Serializer、路由）生成 OpenAPI schema，并通过 Swagger UI 提供可交互的 API 文档页面。开发者无需手动编写文档，且代码更新后文档自动同步。

### 5.2 后端实现

#### 5.2.1 数据模型实现

以核心模型 ProductBatch（产品批次）为例：

```python
class ProductBatch(models.Model):
    product = models.ForeignKey(Product, on_delete=models.CASCADE, related_name='batches')
    batch_code = models.CharField(max_length=100, unique=True, default=uuid.uuid4)
    harvest_date = models.DateField(null=True, blank=True)
    quantity = models.PositiveIntegerField(default=0)
    images = models.JSONField(default=list, blank=True)
    trace_info = models.JSONField(default=dict, blank=True)
    qc_report = models.CharField(max_length=500, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
```

`batch_code` 字段使用 UUID 生成唯一标识，确保每个批次在全球范围内的唯一性。`trace_info` 字段采用 JSON 格式存储灵活的溯源数据，可容纳种植记录、施肥记录、农药使用记录、运输记录等结构化信息。

#### 5.2.2 REST API 实现

采用 ViewSet + Router 模式实现 REST API，以 ProductViewSet 为例：

```python
class ProductViewSet(viewsets.ModelViewSet):
    queryset = Product.objects.select_related('farmer').all()
    serializer_class = ProductSerializer
    permission_classes = [permissions.IsAuthenticatedOrReadOnly]
```

通过继承 `ModelViewSet`，自动获得 `list`、`create`、`retrieve`、`update`、`destroy` 五个标准操作。`select_related` 优化 N+1 查询问题。`IsAuthenticatedOrReadOnly` 权限策略允许匿名用户浏览产品，仅认证用户可以创建和编辑。

#### 5.2.3 序列化器实现

OrderSerializer 实现了嵌套写入，以支持订单及其明细的原子性创建：

```python
class OrderSerializer(serializers.ModelSerializer):
    items = OrderItemSerializer(many=True)

    def create(self, validated_data):
        items_data = validated_data.pop('items')
        order = Order.objects.create(**validated_data)
        total = 0
        for it in items_data:
            OrderItem.objects.create(order=order, **it)
            total += it['price'] * it['quantity']
        order.total_amount = total
        order.save()
        return order
```

### 5.7 数据可视化驾驶舱

数据驾驶舱是平台的运营数据总览页面，通过 ECharts 实现四种数据可视化组件。

#### 5.7.1 统计 API 端点

统一的后端统计接口 `/api/stats/dashboard/`，聚合返回所有运营数据：

```python
@api_view(['GET'])
def dashboard_stats(request):
    total_products = Product.objects.count()
    total_farmers = FarmerProfile.objects.count()
    total_orders = Order.objects.filter(status='delivered').count()
    total_coops = Cooperative.objects.count()
    # 月销量趋势（按月份聚合已完成订单）
    monthly_sales = Order.objects.filter(status='delivered')\
        .annotate(month=TruncMonth('created_at'))\
        .values('month')\
        .annotate(total=Sum('total_amount'), count=Count('id'))\
        .order_by('month')
    # 产品分类分布
    category_dist = Product.objects.values('category')\
        .annotate(count=Count('id')).order_by('-count')
    return Response({...})
```

#### 5.7.2 前端可视化组件

| 组件 | 类型 | 数据来源 | 说明 |
|------|------|---------|------|
| 统计卡片 | 数字展示 | dashboard API | 展示总数 |
| 月销量趋势 | 柱线混合图 | monthly_sales | 销售额 + 订单数 |
| 分类分布 | 环形饼图 | category_distribution | 产品结构 |
| 订单状态 | 柱状图 | order_status | 状态分布 |

前端使用 ECharts 5 CDN 加载，所有图表在页面加载时通过 fetch 获取数据并渲染，支持窗口自适应缩放。

```javascript
fetch('/api/stats/dashboard/')
  .then(r => r.json())
  .then(data => {
    // 初始化柱线混合图
    const chart = echarts.init(document.getElementById('chart-sales'));
    chart.setOption({
      xAxis: { data: data.monthly_sales.map(s => s.month) },
      series: [
        { type: 'bar', data: data.monthly_sales.map(s => s.total) },
        { type: 'line', data: data.monthly_sales.map(s => s.count) }
      ]
    });
  });
```

## 第七章 总结与展望

### 7.1 工作总结

本文设计并实现了一个基于 Django 的农产品溯源与助农平台，主要工作包括：

1. **需求分析与系统设计**：完成了面向消费者、农户、管理员三类角色的功能需求分析，设计了四层系统架构和 9 张数据表。

2. **后端开发**：基于 Django REST Framework 实现了完整的 RESTful API，包括产品管理、订单管理、批次溯源、补贴申请、培训管理等模块。

3. **前端开发**：使用 Bootstrap 5 构建了响应式用户界面，覆盖首页、产品列表、产品详情、溯源查询、登录注册等页面。

4. **溯源系统**：设计了基于 UUID 的批次唯一编码方案，实现了从生产到销售的全链路信息追溯功能。

5. **数据可视化**：基于 ECharts 构建了数据驾驶舱，包含月销量趋势图、产品分类分布饼图、订单状态分布图等可视化组件，实现运营数据的直观展示。

6. **自动化部署**：通过 Docker 容器化技术和 systemd 服务，实现了平台的一键部署和开机自启动。

7. **测试验证**：编写了 23 个单元测试用例，覆盖模型、API、页面、认证四大层面，全部测试通过。

### 7.2 不足与改进

1. **在线支付**：当前采用线下支付模拟方案，未来可集成微信支付、支付宝等在线支付方式。
2. **移动端适配**：虽然 Bootstrap 已提供基础响应式支持，但专用移动应用或微信小程序将提升用户体验。
3. **数据存证**：溯源信息的防篡改能力可进一步通过区块链技术增强。
4. **性能优化**：随着数据量增长，可引入 Redis 缓存、数据库读写分离等优化措施。

### 7.3 展望

未来可以在以下方向继续完善和扩展：

- **智能化**：引入 AI 农产品价格预测、智能推荐等功能
- **数据可视化**：构建大数据驾驶舱，展示农产品交易趋势、溯源数据统计等
- **生态扩展**：对接政府监管平台、第三方检测机构，形成完整的农产品质量保障生态
